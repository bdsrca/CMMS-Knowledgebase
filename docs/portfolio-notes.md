# Portfolio Notes

## How to present this project

A strong portfolio description should focus on the engineering problem, not the AI buzzword.

Suggested summary:

> Built a public-safe CMMS/EAM knowledge-base case study showing how approved maintenance documents can be ingested, indexed, retrieved, cited, and reviewed inside a multi-tenant SaaS workflow.

## What this demonstrates

- CMMS/EAM domain understanding.
- Multi-tenant data modeling.
- Admin-facing source governance.
- Background job design.
- Chunking and embedding workflow.
- Hybrid retrieval and rank fusion.
- Cited answer packaging.
- Privacy-conscious query logging.
- Product thinking around safety, role access, and operational trust.
- Clear public documentation without exposing private implementation details.

## Good talking points

### Not just a chatbot

The system manages source content, indexing, retrieval, citations, and logs. That is different from pasting CMMS context into a prompt.

### Trust before automation

The assistant can explain and route. It does not silently change work orders, inventory, or policy.

### Logs are for improvement

Low-confidence answers and no-result searches become a content backlog for admins.

### Designed for maintenance reality

Maintenance teams use exact asset names, informal phrases, status labels, and local process terms. That is why hybrid retrieval matters.

## Suggested GitHub pinned-repo description

> Public-safe CMMS/EAM knowledge-base case study with tenant-aware source governance, async indexing, hybrid retrieval, cited AI answers, privacy-conscious logs, diagrams, and runnable sample code.
